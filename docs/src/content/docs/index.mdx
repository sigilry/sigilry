Sigilry is a [CIP-103](https://github.com/canton-foundation/cips/blob/main/cip-0103/cip-0103.md) compliant dApp connectivity library for Canton Network. It implements the CIP-103 dApp API as a typed JSON-RPC client/server pair, ships generated Zod schemas for runtime validation, and exposes React Query hooks for fast integration.

Install the stable SDK with `yarn add @sigilry/dapp@^3 @sigilry/react@^3`. Building with Send Connect? Start with [testnet connection](/guides/send-connect-testnet/), [message verification](/guides/verify-sign-message/), and [holdings queries](/guides/read-holdings/).

Sigilry is built and maintained by [Send](https://send.it) and used in production by Send's Canton Network dApps.

## New to Canton?

Start with the [Demo App](getting-started/demo-app/) before package internals. It shows the full flow in one place:

1. DAML templates and choices (`TodoList` factory + `TodoItem` contracts)
2. DAR build and typed codegen via Sigilry CLI
3. dApp-side React hooks calling a typed `window.canton` provider
4. Event-driven wallet/ledger logs plus `txChanged` updates after approvals

Fastest way to run it from the repo root:

```bash
nix develop
yarn install
yarn --cwd examples/demo-app dev
```

Choose your starting path:

- Building a real dApp integration against an installed wallet extension: go to [Quick Start](getting-started/quick-start/).
- Learning the full flow locally without extension setup: go to [Demo App](getting-started/demo-app/).

## SDK Flow

The wallet extension injects a CIP-103 provider at `window.canton`. The provider object follows the
EIP-1193 shape that CIP-103 itself specifies (`request` / `on` / `removeListener`), routes calls through
typed JSON-RPC method names from the CIP-103 OpenRPC schema, and emits the full CIP-103 §4.2.2 push-event
surface (`accountsChanged`, `txChanged`, `statusChanged`, `connected`) to signal wallet, ledger, and
session/network state changes. Methods with void params omit the `params` field. See
[CIP-103 Conformance](concepts/cip-103-conformance/) for the per-method conformance table, and the
[@sigilry/dapp](packages/dapp/) and [@sigilry/react](packages/react/) pages for the full contract.

## CLI Codegen

Use `sigilry init` to create `sigilry.config.ts`, then run `sigilry codegen` to generate TypeScript types.
The CLI requires the DAML SDK so `dpm` is available, and it wraps `dpm codegen-alpha-typescript` under the
hood. See the [@sigilry/cli](packages/cli/) page for the full configuration reference.

## Ledger API Patterns

`ledgerApi` requests map directly to Daml JSON Ledger API v2 endpoints. Hooks like `useLedgerApi` and
`useActiveContracts` call `/v2/state/ledger-end` and `/v2/state/active-contracts` to resolve the current
offset and fetch active contracts.

## Architecture at a glance

```
dApp UI
  -> window.canton (CIP-103 provider; EIP-1193 object shape)
  -> JSON-RPC (CIP-103 OpenRPC schema + Zod validation)
  -> WindowTransport (postMessage)
  -> Wallet extension (RPC server)
  -> Canton Ledger API / DAML
```
